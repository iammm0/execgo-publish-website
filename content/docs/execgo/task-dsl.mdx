---
title: Task DSL
description: The task graph contract used by ExecGo's scheduler and executor layer.
---

The Task DSL is intentionally small. A task declares identity, executor type, parameters, dependency edges, and execution policy.

```json
{
  "id": "fetch",
  "type": "os",
  "tool_name": "http",
  "params": {
    "url": "https://example.com/data.json",
    "method": "GET"
  },
  "depends_on": [],
  "retry": 2,
  "timeout": 10000
}
```

## Fields

| Field | Purpose |
| --- | --- |
| `id` | Stable task identifier used for dependency edges and polling |
| `type` | Executor category such as `os`, `mcp`, `cli-skills`, or `runtime` |
| `tool_name` | Tool inside an executor category, for example `shell`, `file`, or `http` |
| `params` | Tool-specific JSON payload |
| `depends_on` | Upstream task IDs that must finish before this task runs |
| `retry` | Retry count for transient executor errors |
| `timeout` | Per-attempt timeout in milliseconds |

ExecGo validates the graph before execution. Duplicate IDs, unknown dependencies, self-dependencies, and cycles are rejected as a whole submission.
